# Meowcal Sub v0.6.8

A quality release. Everything in it exists because a 34-minute en-US → zh-CN
session was recorded and counted rather than reasoned about, and the count was
uncomfortable: **82% of OCR reads came back clean, but only about two thirds of
viewing time showed a good line.** 11% of the time garbage was on screen, 9% was
blank — and 5% of that blank while OCR was successfully reading text.

Almost none of that was recognition accuracy. It was the pipeline throwing away
lines it had already read correctly. This release stops six ways it did that.

There is no new feature and no new setting here. Every change is automatic.

## Subtitles the app had already read now reach the screen

**A worse re-read no longer replaces a good translation.** One cue is captured
ten or more times while it sits on screen, and Windows OCR returns something
slightly different each time. A clean `However, isn't he a hero from an era` was
followed 0.66 seconds later by `bf//dzz:: However, isn't he a hero from an era`,
and the second, mangled read won simply by being newer. A re-read that grows by a
garbled prefix is now recognised as the same cue read worse.

**A line that is mostly noise is refused before it costs a translation.** There
is one translation slot. Spending it on `Wh€reythe MFtiÄhave relatively;
thinnedput?` means the real dialogue arriving behind it is never translated at
all.

**A two-line cue is no longer translated twice.** OCR returns the top row on one
frame and the bottom row on the next, and comparing each read against only the
previous one made both look like fresh dialogue. The last four lines over a
six-second window are now remembered.

**A real subtitle band can no longer be silenced for a minute and a half.** A
band judged to be churning is now set aside for at most 30 seconds and then
re-admitted. The width-and-character-count test that decides whether a band is
still showing the same cue was also too strict in one direction, so a subtitle
whose read wobbled between 27 and 13 characters was treated as two different
cues; the tolerance is now symmetric.

**A translation that comes back in the wrong script is rejected.** With Chinese
selected as the target there was no equivalent of the check the English target
already had, so `MFtiÄhave` was displayed as if it were a translation.

**The overlay says what is actually happening.** A frame whose every line the
band filter held used to report "no text detected", which sends you to move a
capture region that was never the problem. It now says it is waiting. And a
refused read keeps the last good translation on screen underneath the
explanation, instead of blanking it.

## A bad config read can no longer erase a working engine

A configuration file the app could not parse silently became defaults, and the
next save wrote those defaults back. One unreadable read permanently erased a
working engine registration and your capture region on a machine where every
engine file was intact — and then offered first-run setup for an engine already
sitting on disk.

Loading now tells "there is no config yet" apart from "there is a config and it
is unreadable". Saving writes through a staging file and an atomic rename, keeps
a last-known-good copy, and quarantines an unusable config rather than
overwriting it.

## A busy machine no longer looks like a broken app

The translation engine runs on the CPU on ARM64. Under background load a call
that normally takes 300ms can turn into a 20-second outage, and the overlay used
to go blank and say nothing.

A line that misses its deadline is now abandoned and reported as the engine
falling behind, with the previous translation kept on screen. The message names
what you can act on — load on the machine — rather than suggesting the engine is
broken.

## Known limitations

- **The blank-and-garbage problem is reduced, not solved.** A re-read that grows
  at the _end_ with its own OCR noise is still translated, because a suffix is
  also how the second row of a two-line cue arrives, and refusing it would mean
  second rows never appear. The similarity threshold is still calibrated on
  Chinese source text; the English separation margin is measurably thinner.
  Tracked as issue #59, which stays open.
- The overlay box changes size when it switches between a translation and an
  empty-state message. Tracked as issue #91.
- The overlay toolbar has no direct translation controls. Tracked as issue #92.
- A configuration that had to be recovered is recorded in the log and not shown
  to you. Tracked as issue #70.
- `minimizeToTray` is stored and still not applied: closing the main window
  always hides it to the tray.
- The update check is manual. There is no notification when a release appears.
  Tracked as issue #61.
- Each band's translation is still shown in the single overlay rather than near
  the text it came from. Tracked as issue #57.
- Windows OCR splits some characters into their radicals, and preprocessing was
  confirmed unable to fix it. Tracked as issue #53.
- Capture is fixed to the primary monitor while the overlay covers every display.
  Tracked as issue #52. Single-monitor setups are unaffected.
- Installers are not code-signed. Beyond the expected SmartScreen prompt,
  Microsoft Defender has been observed deleting `meowcal-sub.exe` outright after
  installation, taking the Start Menu shortcut and uninstall entry with it. The
  detection is `Trojan:Win32/Bearfoos.A!ml` — a machine-learning heuristic, not a
  signature match, and a false positive. It presents as the app vanishing rather
  than as an antivirus warning. Until the binaries are signed, recovering needs
  an elevated `Add-MpPreference -ExclusionPath` for the install directory before
  reinstalling. Tracked as issue #62.

## Before installing

- Windows 11 is the supported target.
- Choose ARM64 for Snapdragon/ARM Windows PCs and x64 for Intel or AMD PCs.
- Verify manual downloads against `SHA256SUMS.txt`.
- The local translation runtime and model require a one-time download of about
  1.1 GB.

## Validation status

The full automated repository gate passed on the released commit: Rust format,
clippy, unit and IPC integration tests on both shipped architectures, frontend
format, lint, typecheck, production build, unit tests, the browser-to-Rust smoke,
the maintainability ratchet, and the dependency audit.

The subtitle-quality work was manually validated on native Windows 11 ARM64
against a real en-US → zh-CN session, and the resulting quality was judged good
enough to release. That is a human judgement on live playback, not a re-run of
the 34-minute measurement above: the percentages in this document describe the
problem as measured on 0.6.6, not a measured improvement over it.

The x64 package is built by the same script and has not had an equivalent
manual check.
