# Meowcal Sub v0.9.0

This release reads subtitles with a new built-in recognizer, PP-OCRv6, so an
unchanged subtitle is read the same way from frame to frame and is translated
once. It also adds an Exit control to the subtitle overlay and keeps the overlay
on the monitor you capture.

## New

- **PP-OCRv6 text recognition.** Meowcal now reads subtitles with PP-OCRv6
  small, running on your PC inside Meowcal Core. Windows OCR often read an
  unchanged subtitle several ways, and each new reading started a new
  translation. On a recorded Chinese clip, every one of 40 subtitles was
  translated once and correctly, against 27 of 40 correct and 3 missed with
  Windows OCR. PP-OCRv6 reads Chinese, Japanese, English, Spanish, French and
  German without a Windows language pack (#59).
- **Settings → Profile.** **Automatic** reads with PP-OCRv6 and lets
  translation use the graphics card when it can. While translation runs on
  the CPU, PP-OCRv6 uses two CPU threads instead of four, so recognition leaves
  room for the translation engine. **Compatibility** reads with Windows OCR
  and translates on the CPU. The individual choices are under **Advanced**.
  Korean subtitles always use Windows OCR, because PP-OCRv6 cannot read Hangul.
- **Exit from the overlay.** The subtitle overlay has an Exit control that stops
  translation and returns to Home. It sits outside the captured area and works
  from the keyboard (#92).

## Fixes and improvements

- The translated overlay stays on the monitor that holds the selected subtitles
  when a second display sits left of the primary one.
- Confirming a subtitle area starts preparing the translation engine, so model
  loading overlaps the time before you press Start.
- Small text in the subtitle row, such as a channel watermark, is left out of
  the subtitle that PP-OCRv6 reads.
- On x64 PCs, translation uses the graphics card only when the PC has a
  discrete GPU. PCs with only integrated graphics translate on the CPU, which
  was faster in testing, and Settings now says so (#305).

## Validation

Both recognizers were read through the app's recognition path against a
source-built Meowcal Core 0.2.0 on Windows ARM64, and the app's subtitle policy
was replayed over the reads of a real Chinese clip and synthetic Chinese and
English clips. The results are in
[the OCR stability experiment](../plans/2026-11-05-ocr-stability-experiment.md).
The installed release build was also run on a Snapdragon X Elite against the
band-gate fixture with translation forced to the CPU: both recognizers
translated 29 of 30 cues while idle and while four other threads kept the CPU
busy. With eight busy threads, translation fell behind with either recognizer.
Hosted Windows x64/ARM64, Linux development and CodeQL checks passed on the
merged main commit.

## Known limitations

- PP-OCRv6 uses about 50-100 ms of CPU per captured frame on a Snapdragon X,
  against 5-30 ms for Windows OCR. When other programs keep the CPU busy and
  translation runs on the CPU, translation can fall behind with either
  recognizer.
- The installers are about 30 MB larger, because Meowcal Core now contains the
  PP-OCRv6 models.
- A watermark or sign in the selected area can still be translated on its own
  while no subtitle is showing. Draw the area tightly around the subtitles.
- GitHub installers are not Authenticode-signed. Windows SmartScreen may show an
  unknown-publisher warning; updater signatures do not remove it (#62).
- ARM64 GPU acceleration remains limited to the validated Adreno X1-85 and
  driver 31.0.148.0 (#105, #215).
- On x64, a discrete GPU whose Vulkan driver does not work can leave
  translation on the CPU while Settings shows the GPU.

This release bundles Meowcal Core v0.2.2. Choose the installer matching your
Windows architecture and verify downloads with `SHA256SUMS.txt`.
