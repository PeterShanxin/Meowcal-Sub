# Meowcal Sub v0.8.6

This release fixes reading of burned-in Chinese subtitles, which on real
episodes often came out as broken characters and could not be translated.

## Fixes

- **White subtitles on bright scenes read correctly.** Burned-in subtitles are
  usually white text with a dark outline. Over a bright background, such as a
  yellow wall or a sky, the text used to reach Windows OCR as hollow outlines,
  and Chinese lines came back split into radicals (for example `另刂` for `别`).
  Subtitle mode now picks out the white text by colour and leaves a blank
  margin around the frame, so characters that touch the edge of the capture
  area are no longer split. If that finds no text, recognition falls back to
  the previous method, so coloured subtitles still read as before.
  **Translate any text** is unchanged (#53).

## Windows / ARM64 notes

- Each installer carries Meowcal Core v0.1.3 for its architecture, unchanged
  from v0.8.5. Downloaded runtime and model files are reused.
- GPU acceleration remains limited to the validated Adreno X1-85 with driver
  31.0.148.0; other ARM64 hardware uses CPU inference.
- Windows 11 ARM64 native testing on CPU, with a full real episode played
  through (Chinese burned-in subtitles to English):
  - 430 lines translated, 399 of them distinct.
  - Median time from capture to translated overlay: 236 ms.
  - Pausing and seeking behaved normally.
  - One engine process throughout.
- In an offline replay of seven frames from the same episode, the v0.8.5
  recognition path read none correctly. The new path read five exactly or
  with one character wrong, and a sixth mostly right.

## Known limitations

- White objects in the scene that touch the subtitle line, such as plates or
  tablecloths, can still merge into the text and cause misreads (#251).
- Each Meowcal Core version keeps its own copy of the engine files, and older
  copies are not removed yet. Uninstalling also leaves them in
  `%LOCALAPPDATA%\Meowcal\Core` (#252).
- The cause of the Adreno numerical corruption remains unresolved (#105).
  Automatic CPU fallback and the CPU-only setting reduce GPU exposure but are
  not proven to prevent the reported `SOC_CRITICAL_DEVICE_REMOVED` Windows stop
  error (#215).
- The x64 installers receive automated build and contract checks; physical x64
  was not validated for this release.
- First translation waits for model loading, which can take longer under memory
  pressure. CPU inference latency varies by device.
- General screen text still shares the subtitle prompt and change-detection
  rules (#181, #187).
- Installers are not Authenticode code-signed. Windows SmartScreen may show an
  unknown-publisher warning.

Choose the installer matching your Windows architecture and verify downloads
with `SHA256SUMS.txt`. The local runtime and model require a one-time download;
verified files from an earlier Core version can be reused.
