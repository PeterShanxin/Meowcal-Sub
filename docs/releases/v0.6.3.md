# Meowcal Sub v0.6.3

A latency and correctness release. Subtitles appear sooner, one line produces
one translation instead of two or three, and the app's own title bar works.

Everything below was diagnosed from session logs of a Chinese-to-English
episode rather than reasoned about, so the causes are recorded alongside the
fixes.

## Latency

- The capture interval was stuck at 500ms whatever the backend defaulted to.
  The frontend keeps its own copy of every default and posts the whole settings
  object back on save, so its stale 500 overwrote the backend's 250 every time
  anything was saved — and no setting exposes the field, so it could not be
  corrected by hand. That was up to half a second of pure delay before a new
  subtitle was even looked at. Stored settings carrying the stale value are
  migrated on load.
- Image preprocessing collapses from four passes over the capture region, each
  allocating an intermediate image, into two passes and a lookup table. On a
  3006x214 region that is 5.4ms down to 3.5ms in a release build, and 119ms
  down to 37ms in a development one. The output is byte-for-byte identical.
- The capture loop paces to a deadline, so a slow frame no longer stacks a full
  interval on top of itself.

Measured end to end, the work around the translation model dropped from roughly
395ms per frame to under 30ms. What remains is the model itself.

## One line, one translation

Reads of the same subtitle were compared for exact string equality, and the
logic that would have recognised a re-read lived behind the context-aware
translation setting, which is off by default. A subtitle sits on screen for
seconds while the loop reads it ten or more times, and Windows OCR does not
return the same characters every time, so each variation looked like fresh
dialogue and earned its own translation.

The comparison now runs for every session, and its threshold is calibrated
against a real episode: re-reads of one subtitle scored 0.50 to 0.85 character
similarity, while genuinely different dialogue never exceeded 0.25. In that
sample, 26 of 63 translations were re-reads of a line already on screen.

## What OCR hands back

- Chinese and Japanese are recognised a character at a time and joined with
  spaces, so a subtitle reached the translator as "亻 每 里 解 什 么 是 魔 术 师".
  Spacing is now closed up for scripts that do not use it, while Latin word
  spacing, mixed-script boundaries and real numbers are left alone.
- Noise at the edge of the capture region — a letterbox border, the corner of a
  logo — was being resolved into a stray character, which is where the bare "0"
  inside translated dialogue came from. A lone digit or quote mark stranded
  beside CJK text is dropped. Sentence punctuation and lines that are genuinely
  just a digit are kept.

## Window chrome

- The title bar introduced in 0.6.2 rendered three buttons that could not work.
  The permission set granted the app let it read whether the window was
  maximised but not minimise, maximise, close or drag it, so every control was
  rejected silently — leaving an undecorated window that could not be moved or
  closed from its own chrome.
- The title bar logo was a fixed asset path that resolved during development and
  was missing from the packaged build.
- Minimising to tray fired the same events as dragging the window, carrying the
  minimised window's geometry. Saving it reopened the app as a small square in
  the corner of the screen on the next launch.

## Known limitations

- Windows OCR sometimes splits one character into its radicals — 你 read as
  "彳 尔". The fixes above clean up after that rather than prevent it, and it is
  the remaining source of imperfect lines.
- Capture is fixed to the primary monitor while the overlay covers every
  display, so a capture region placed on a secondary monitor reads the wrong
  pixels. Tracked as issue #52. Single-monitor setups are unaffected.
- Translation latency is now dominated entirely by the local model. The overlay
  diagnostics panel reports total and model time per line.
- The installer asks whether to uninstall the previous version before upgrading.
  "Do not uninstall" is the correct answer and the default.

## Before installing

- Windows 11 is the supported target.
- Choose ARM64 for Snapdragon/ARM Windows PCs and x64 for Intel or AMD PCs.
- Installers are not code-signed. Windows SmartScreen may show an
  unknown-publisher warning; verify downloads against `SHA256SUMS.txt`.
- The local translation runtime and model require a one-time download of about
  1.1 GB.

## Validation status

The full automated repository gate passed: Rust format, clippy, unit and IPC
integration tests, frontend format, lint, typecheck, production build, unit
tests, the browser-to-Rust smoke, and the maintainability ratchet.

An ARM64 build of this code was installed from its own package and watched
against a Chinese-to-English episode, which is where the assessment above comes
from. The x64 package is built by the same script and has not had an equivalent
check.
