# Meowcal Sub v0.6.9

This release improves ARM64 translation under sustained desktop load and makes
local engine setup more dependable.

## Highlights

- ARM64 systems with the validated Adreno configuration can now use GPU
  acceleration while keeping the translation model unchanged.
- Engine extraction now completes correctly during setup and preserves the
  useful cause when an installation fails.

## Performance & reliability

The ARM64 GPU path is tuned for the worst stalls rather than peak median speed.
Measured sessions showed a much shorter latency tail and far less engine CPU
contention, while median latency was slightly higher. GPU startup also takes a
few seconds longer while the model is loaded. GPU startup failure falls back to
CPU within the same bounded startup deadline.

## ARM64

Production translation continues to use `HY-MT1.5-1.8B-Q4_K_M`. GPU acceleration
is enabled only for the validated **Qualcomm Adreno X1-85 with driver
31.0.148.0**, using full layer offload with the KV cache kept on the CPU
(`-ngl 99` and `--no-kv-offload`). Other or unvalidated ARM64 hardware and
drivers continue to use the prior CPU policy. x64 Vulkan behavior is unchanged.

## Fixes / other improvements

- Failed engine extraction reports the archive and the underlying tool error
  instead of a generic or misleading PowerShell trailer.
- Release and developer tooling now discovers the installed Windows toolchain
  and starts the self-hosted runner with a controlled environment.

## Known limitations

- ARM64 GPU acceleration is intentionally limited to the validated hardware and
  driver combination; the general mid-session hung-engine watchdog remains
  tracked separately as issue #103.
- Update checks remain manual. Installers are not Authenticode code-signed, so
  Windows SmartScreen may still show an unknown-publisher warning.

Choose the installer matching your Windows architecture and verify downloads
with `SHA256SUMS.txt`. The local runtime and model require a one-time download.
