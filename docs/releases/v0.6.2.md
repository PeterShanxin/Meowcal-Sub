# Meowcal Sub v0.6.2

The first 0.6.x release intended for real use. 0.6.0 and 0.6.1 were prepared as
drafts but never published: subtitles that Windows OCR read perfectly well were
being discarded before they reached the translator, so neither build could carry
an episode.

## Subtitles now reach the translator

- Stops rejecting legible subtitles. OCR results were scored by a "confidence"
  that Windows OCR does not actually provide — it was computed from the shape of
  the recognised text, so short lines, sparse punctuation and ellipses all
  pushed real dialogue below the cut. Lines are now judged only on what the text
  can support, and the strictness setting sets a minimum glyph count instead of
  a threshold no engine could populate.
- Fixes the image OCR was being given. A subtitle strip is a few percent glyphs
  over whatever the video is showing, and the old contrast pass redistributed
  brightness by pixel rank, which promoted almost half of a typical background
  to the same white as the letters. Thresholding is now derived from where the
  light and dark parts of the frame actually sit, and normalises light-on-dark
  subtitles and dark-on-bright ones alike.
- Clears the overlay when the capture region goes blank, and says so, instead of
  leaving the previous translation sitting over the video.
- Explains itself when a line is read but not translated, rather than reporting
  an empty region while text is plainly inside it.

## Overlay

- The subtitle panel is genuinely translucent. WebView2 transparency does not
  hold on this platform, so panel opacity moved to the window itself.
- The eight resize handles and the settings gear sit on the frame edge where
  they belong, and the capture area stays a hole in the window.
- The overlay stays responsive while the box is dragged or resized; identical
  geometry is no longer resent every animation frame.
- A hidden settings popup no longer swallows clicks across the whole screen.
- Turning off Show Diagnostics no longer leaves a white block over the video.
- The gear menu gains a Light Background toggle. Black is the default.

## Application window

- The app draws its own title bar on the main and setup windows in place of the
  system chrome.
- The setup progress spinner animates instead of sitting frozen, which made a
  slow install look like a hang.
- One tray icon instead of two, and it responds to clicks.

## Known limitations

- Capture is fixed to the primary monitor while the overlay covers every
  display, so a capture region placed on a secondary monitor reads the wrong
  pixels. Tracked as issue #52. Single-monitor setups are unaffected.
- Translation latency is dominated by the local model, not the capture loop.
  The overlay diagnostics panel now reports total and model time per line so
  this can be measured rather than guessed at.

## Before installing

- Windows 11 is the supported target.
- Choose ARM64 for Snapdragon/ARM Windows PCs and x64 for Intel or AMD PCs.
- Installers are not yet code-signed. Windows SmartScreen may show an
  unknown-publisher warning; verify downloads against `SHA256SUMS.txt`.
- The local translation runtime and model require a one-time download of about
  1.1 GB.

## Validation status

The full automated repository gate passed: Rust format, clippy and tests,
frontend format, lint, typecheck, unit tests, the browser-to-Rust smoke, and the
maintainability ratchet.

This build was watched through a complete 27-minute Chinese-to-English episode
from a development run. The packaged installers have not had an equivalent
end-to-end check, and the overlay behaviour above was verified in the
development build rather than from an installed copy.
